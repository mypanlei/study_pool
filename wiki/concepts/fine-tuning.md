# Fine-tuning（微调）

> 在预训练模型基础上，用特定任务数据继续训练以适应特定场景的方法。从全量微调到高效微调（LoRA/QLoRA），是 LLM 适配落地的核心手段。

## 微调类型

| 类型 | 训练参数量 | 显存 | 适用场景 |
|------|-----------|------|---------|
| **全量微调** | 100% | 极高 | 领域大模型 |
| **LoRA** | 0.1-1% | 低 | 任务适配 |
| **QLoRA** | 0.1-1% | 极低（4bit） | 单 GPU 微调 |
| **Adapter** | 1-5% | 低 | 多任务切换 |

## SFT（Supervised Fine-tuning）

使用人工标注的高质量问答数据对模型进行监督学习，是 RLHF 流程的前置步骤。DeepSeek-R1 的"冷启动"阶段即使用 SFT。

## 与 LoRA 的关系

- LoRA 是高效微调（PEFT）的代表方法
- 详见 [[wiki/concepts/lora-low-rank-adaptation]]

## RAG vs 微调

RAG 和微调解决不同维度的 LLM 落地问题：

| 维度 | RAG | 微调 (Fine-tuning) |
|------|-----|-------------------|
| **知识更新** | 更新知识库/索引即可 | 需重新准备数据并训练 |
| **数据安全** | 知识保留在外部库，按需检索 | 训练样本中的知识固化到参数中 |
| **幻觉控制** | 可引用原文，便于溯源校验 | 模型仍可能编造，来源不天然可见 |
| **成本结构** | 检索 + Token + 向量库 | 数据标注 + GPU 训练 + 评测 |
| **适合场景** | 知识密集型问答、实时信息 | 风格适配、格式控制、术语对齐 |
| **主要风险** | 检索不到、召回噪声 | 数据过拟合、知识过期、回滚成本高 |

> 选型原则：知识变动频繁、需要引用来源 → 优先 RAG；输出风格和任务行为不稳定 → 考虑微调；两者可结合使用。
